# Content architecture for publishers

- Source: https://www.hygraph.com/blog/content-architecture-for-advanced-publishing
- Fetched: 2026-09-23
- Status: ok

## Summary

A follow-on to the PDF-workflow essay. Content architecture is the blueprint: taxonomies, models, relations, workflow, and how a piece is delivered. For intelligence publishers the post says the blocks are metadata, modular components separated from design, explicit content types, and a path from analyst to editor to publish.

Headless delivery is what lets the same piece become a site, an app, mail, or voice. A PDF CMS is treated as evidence the architecture is still page-shaped.

## Key facts

- Architecture covers organisation, links between pieces, channel delivery, and the ability to add types without a rewrite.
- Workflow is a first-class block: who touches the piece, when, and how versions are approved.
- Audience is B2B information publishers with technical, high-volume content.

## How it works

Define types and relations before designing pages. Store text and media as components. Attach taxonomy so search and cross-links work. Run the editorial path in the CMS. Frontends query the model and decide presentation.

## Implications for uiaas.uk / ui121

A task UI needs the same blueprint: types, relations, and a workflow, with presentation decided at delivery. ui121 can talk about “interface architecture” in this vocabulary so content buyers recognise it. The design stays out of the stored object; the renderer applies it.
