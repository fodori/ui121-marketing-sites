# Headless CMS versus page builders

- Source: https://www.hygraph.com/blog/headless-website-builder
- Fetched: 2026-09-23
- Status: ok

## Summary

Katie’s comparison (updated 12 June 2026) puts page builders and headless CMSs at opposite ends of a simple-to-complex line. Squarespace, Wix, and Webflow ship themes and drag-and-drop so a small team can launch without a developer. Content lives on a page template. Reuse means copy and paste, and backend workflow is thin.

A headless CMS stores components (hero, testimonial, product fields, SEO) with no page attached. Editors recombine them after a developer has defined the set. The API feeds web, apps, kiosks, and chat. Setup costs more; the ceiling is higher. The post, written by a headless vendor, still grants page builders the brochure-site use case.

## Key facts

- Page builders fit portfolios, tiny marketing teams, and a few standard pages. They fit poorly when the brand wants full design control, frequent updates, or global workflow.
- Headless fits many content types and sources, many regions, custom integrations, and revenue that depends on digital. It fits poorly with no developers and no plan beyond one site.
- Middle-market choice the post names: start on a builder and replatform later, or pay the modelling cost now.

## How it works

A builder binds content to a template and hosts the site. A headless CMS binds content to a model and lets any frontend query it. Once components exist, editors assemble pages without a developer beside them. Integrations and permissions are API features, not theme settings.

## Implications for uiaas.uk / ui121

Page builders are UI-as-a-template. Headless CMS is content-as-an-API. ui121 is closer to a third point: interface-as-an-API, with enough structure that non-developers can assemble a task without owning a React app, and enough of a contract that the result is not trapped in one vendor’s theme.
