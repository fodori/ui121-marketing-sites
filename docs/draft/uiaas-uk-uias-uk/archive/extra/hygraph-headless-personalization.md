# Headless personalization maturity

- Source: https://www.hygraph.com/blog/headless-personalization
- Fetched: 2026-09-23
- Status: ok

## Summary

Pia Pekkala at Solteq, published via Hygraph, says personalisation projects fail from missing goals, from pouring unused data into an engine, from siloed tools, and from expecting instant return. One client rebuilt the data feed and doubled the cost because most of the feed was irrelevant.

Solteq’s maturity ladder has five steps: manual one-to-one, a single message with a name, rule-based segments, model-based intent, and real-time hyperpersonalisation. Most companies should stop between rules and models. Netflix-scale hyperpersonalisation is called a poor target for everyone else.

## Key facts

- Early personalisation can be a CRM plus a CMS. Later stages add analytics and a headless CMS to feed many channels.
- Content volume (copy, tone, images per segment) is the hidden cost; AI and a structured CMS are how the post says you survive it.
- A pre-study offer from Solteq is mentioned; no numeric ROI is stated as Solteq’s own result.

## How it works

Start with the signals that matter, segment with rules, serve content variants from a headless CMS, then let models suggest intent once the rules pay off. Do not run search, recommendations, marketing automation, and loyalty as four unrelated programmes.

## Implications for uiaas.uk / ui121

Experimenting on task UIs will fail the same way if every variant is a new screen build. A schema with variants, aimed at rule-based segments first, is the practical offer. Hyperpersonalisation is a later chapter. The data warning is real: ui121 should consume a few clear signals, not a warehouse dump.
