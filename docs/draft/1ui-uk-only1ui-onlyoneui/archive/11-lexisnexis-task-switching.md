## Summary

LexisNexis Enterprise Solutions’ 10 September 2025 Visualfiles post applies the task-switching literature to legal casework. The arithmetic they lead with: five switches a day can cost nearly two hours; over a year, more than 500 hours per employee. They cite an average of 23 minutes and 15 seconds to get back on track after an interruption, and a 20% to 40% loss of productive time per switch from reorientation. The root cause they name is too many tools and too little integration.

The concrete scene is a conveyancing file. Someone opens the case system, then the Land Registry, then the EPC register, then a separate client due-diligence and ID/AML system. If the accounts package is not linked, names and addresses are retyped. The same pattern is general: Slack versus Teams, a case system versus email and network folders, a CRM beside a document store. Double entry is framed as error risk, not only lost time. Memory and stress are the human layer: frequent switching is tied to weaker working memory and a path toward burnout. Hiring more people is called a costly patch that multiplies the same bad experience.

The product answer is Lexis Visualfiles and Lexis Everyfile: one to-do list as a command centre, workflows that open websites and documents without leaving the environment, APIs and .NET integrations, and “robots” that send chase letters and reminders until a response arrives. Delegation keeps a task visible when it moves between people.

## Key facts

- Five task switches a day ≈ nearly two hours lost per day; more than 500 hours a year per employee (their illustration).
- 23 minutes 15 seconds average to get back on track after an interruption or switch.
- 20–40% of productive time lost per switch to reorientation, as stated on the page.
- Example systems in one file opening: case management, Land Registry, EPC register, ID/AML, and a separate accounting package.
- Named products: Lexis Visualfiles, Lexis Everyfile; integrations via APIs and .NET; automated chase/reminder “robots.”

## How it works

Fragmentation forces a human to be the integration layer: open system A, copy, open system B, paste, remember which folder held the letter. Their platforms invert that. The professional stays in one workspace; the workflow calls out to registries and documents; repetitive follow-ups run on a timer; handoffs stay on a shared list. The employee’s attention stays on the matter instead of on navigation.
