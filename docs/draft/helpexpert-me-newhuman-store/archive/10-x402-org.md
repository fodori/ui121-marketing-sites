# x402.org

- **Source:** https://x402.org/
- **Fetched:** 2026-09-23
- **Status:** ok

## Summary

x402 is an open payment standard that revives the unused HTTP status “402 Payment Required” so a client, including an AI agent, can pay for a request the way it already exchanges data. The site, last updated in the page metadata on 25 August 2026, calls itself neutral and internet-native, aimed at agent-scale payments and a “more free and fair internet.” A button leads to the Linux Foundation launch announcement (saved separately as source 25).

The homepage dashboard for the last 30 days showed 75.41 million transactions, $24.24 million volume, 94,060 buyers, and 22,000 sellers. Those are protocol-level totals, not RentAHuman’s volume.

The integration claim is a single middleware line: declare which route costs money, on which networks. If a request arrives unpaid, the server answers 402 and the client pays and retries. The “about” section argues that account forms are a human habit and do not match programmatic clients. Feature slogans are zero protocol fees (networks still charge their own fees), zero wait, zero accounts or personal data, zero centralization, and zero tie to one chain. A comparison contrasts the old API-monetization path (create an account, add a card, buy credits, manage a key, then pay slowly) with three steps: receive 402, pay in stablecoins, get access without key management.

FAQs say the protocol is for API monetization, agent commerce, and paywalled content; that it is production-ready, open source, and security-audited, with millions of transactions; that integration is one middleware line with docs in several languages; and that it is chain-agnostic (EVM, Solana, and more), with stablecoins as the main case and room for traditional methods. A get-started link points at seller docs on docs.x402.org. This note does not expand that docs site; the extra-page cap was used on RentAHuman’s own docs and blog.

## Key facts

- 30-day figures on the page: 75.41M transactions, $24.24M volume, 94.06K buyers, 22K sellers.
- Flow: unpaid request → HTTP 402 → stablecoin payment → retry.
- No protocol fee; no account required for the happy path they advertise.
- Chain-agnostic; stablecoin-first; cards mentioned as something the design can extend to.
- Seller quickstart lives at docs.x402.org (linked, not archived here).

## How it works

The server marks a route as paid. A client that understands the challenge pays the exact amount on an accepted network and repeats the HTTP call with proof. Humans can use the same pattern; the page’s emphasis is agents that cannot fill checkout forms.

## Implications for helpexpert.me / newhuman.store

This is the rail that makes “an agent pays a human a few dollars for one answer” plausible without a card form. It does not match the human, hold escrow, or check the answer. RentAHuman already sits on top of it for wallet top-up. A later knowledge product can use the same rail for per-question prices and still own the ask/answer object. Quote the 30-day totals as protocol adoption, not as demand for human help. Do not promise zero fees: the site itself says network fees remain.
