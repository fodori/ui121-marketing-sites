## Summary

v0’s homepage, as fetched, is a product for building software from a prompt, not a runtime that paints UI from a catalog while an agent is talking to a user. The pitch: describe a feature, refine a design, update copy, or make a live prototype, then deploy, or open a pull request. Capabilities listed: prompts in the user’s language, high-fidelity UI from wireframes or mockups, a backend connection for data-driven apps, one-click deploy on Vercel, and automatic error fixing.

The audience split is a product-marketing map. Product managers prototype plans, interview scripts, feedback forms, and RFC templates. Designers turn screenshots or Figma into interface, CSS, and accessible basics. Engineers scaffold React, hooks, and current Next.js features. Data scientists are pointed at Snowflake, Python, SQL, and charts. Marketing teams get landing pages, SEO research, and email drafts. Educators get exercises and visual explanations. Support teams get chatbots and knowledge-base tools. Founders get an MVP without hiring a team first.

Differentiation claims: UI and backend together, not only mockups; a stack of Next.js, Tailwind, and shadcn/ui; collaboration across design, product, and engineering; bring-your-own APIs, databases, and components; an agent that can search, inspect a site, fix errors, and call tools; a live preview of the agent’s actions; multimodal generation, browsing, debugging, and APIs in one place. The page points at a docs sitemap, an llms.txt index, and an agents.md for API and MCP discovery. Those are v0’s own documentation indexes. They describe a code-generation product, not the data-driven UI category this research set is collecting, so they were not expanded into the 25-extra cap. The generative-UI story for v0’s early behaviour is the November 2023 Griffiths Waite study (source 32).

## How it works

The user prompts. v0 generates and iterates application code, shows a preview, and can deploy that application. Components come from a modern React stack the model has been taught, which a developer can then own as source. That is artifact generation. The running app is ordinary code, not a stream of component messages interpreted by a host catalog on each user turn.

## Implications for generatedui / ui121

v0 is the name people will confuse with generatedui.app. The distinction to put in the first paragraph of any launch page: v0 builds an app you deploy; ui121 renders an interface from data at runtime, using blocks you already approved. Both can be true in one company — v0 or similar tools to author the block library, ui121 to let an agent assemble those blocks per task via MCP. Do not claim v0’s deploy or shadcn pipeline as a ui121 feature. The homepage’s MCP mention is discovery for v0’s own agent surface, not the MCP Apps UI spec.
