The indexed definition: generative UI would use AI to create and adjust layout and design of sites and apps from what it learns about each user, so the experience is more personal and more responsive. In the future tense of the piece, interfaces are created dynamically in real time. That forces an outcome-oriented design approach: designers prioritise user goals and define the constraints the AI may operate inside, rather than drawing every element.

The excerpt says success depends on foundations that are not glamorous: content, information architecture, technical architecture, and a design system where design and code already match. Without those, a generative system cannot stay coherent. The piece also warns that the usual story of Gen UI lets the business and the technology infer preferences, instead of letting people state and control how they want to be augmented. It is explicit that the capability “isn’t here just yet” in the voice of that article — which fits a 2024 publication, before A2UI and MCP Apps. The upside named is personalisation at interaction level, not marketing-segment level. The open questions named are user control versus inference, and how brand and creativity survive inside generated interfaces.

A Nielsen Norman Group article on generative UI and outcome-oriented design uses closely related language (constraints as guardrails, the risk that a UI which changes every visit destroys learnability). That NN/g piece is a cousin of this argument, not a substitute for Tulloch’s full text.
